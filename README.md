# Multipart Object Commit Lab

Development version **0.1.0**, by **Lofrano Tecnologia**. Original MIT-licensed PHP software demonstrating multipart admission, digest deduplication, atomic batch visibility, and recovery across the local filesystem/SQLite commit gap. It is a bounded local laboratory, not a deployment recommendation or a production-readiness claim.

[Português](README.pt-BR.md) · [Contract](docs/contract.md) · [Design](docs/design.md) · [Recovery](docs/recovery.md) · [Runtime qualification](docs/runtime.md)

## Install and qualify

Requires Linux, PHP 8.4+ CLI/FPM with PDO SQLite, POSIX and hash, nginx, curl, and `setsid`. No Composer packages. The harness refuses UID 0. All server processes, workers, sockets, temporary files and logs run under its unprivileged UID; no system service is started.

The linked SQLite library must be **3.54.1**, above the minimum 3.51.3. The pinned PHP base and public `dependency-metadata/sqlite-source.json` identify the official source URL, archive checksum, amalgamation checksum and expected SQL source ID. The image verifies those pins, builds the shared library and qualifies actual PDO SQL/FTS5 before accepting it. No repository variables or secrets are required. See [runtime.md](docs/runtime.md).

```sh
docker build -t multipart-object-commit-lab:local .
docker run --rm --network none multipart-object-commit-lab:local php bin/qualify.php
docker run --rm --network none --read-only --tmpfs /tmp:rw,nosuid,nodev,size=192m multipart-object-commit-lab:local php tests/run.php
docker run --rm --network none --read-only --tmpfs /tmp:rw,nosuid,nodev,size=192m multipart-object-commit-lab:local php bin/demo.php
```

Dependency preparation occurs only during the image build. The image records installed Debian package versions and actual SQLite source ID. No nested container engine, privileged container, credentials or external runtime API is used. On an already qualified unprivileged host, from an ASCII installation path:

```sh
php bin/qualify.php
php tests/run.php
php bin/demo.php
php bin/demo.php --json
```

Tests and demo launch private nginx/FPM instances themselves. They do not use an existing web server. Each scenario has a ten-second controller deadline. Namespace removal happens only after owned clients and master process groups have been shut down and reaped.

## What the demo asserts

Seven deterministic scenarios use only synthetic `abc`, `xyz` and generated bytes. They cover two-file publication, physical deduplication across separate batches, an oversized final file and a five-file request, crashes on both sides of SQLite commit, two concurrently admitted identical uploads, and traversal-style labels. Random paths/PIDs/batch IDs are deliberately excluded from the report. Results are asserted using curl byte retrieval, independent directory inventory, known SHA-256 vectors and direct SQL queries.

Example final output line, after the seven human-readable `PASS` lines:

```json
{"version":"0.1.0","ok":true,"scenarios":["two-file publication and independent byte/SHA/SQL oracles","deduplication preserves separate batch references","oversize final file and five-file request publish nothing","precommit crash leaves only an invisible recoverable orphan","postcommit lost acknowledgement retains one complete batch","concurrent identical uploads rendezvous without lock deadlock","traversal-style labels remain data and caller paths survive"],"vectors":{"abc":"ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad","xyz":"3608bca1e44ea6c4d268eb6db02260269892c0b42b86bbf1e77a6fa16c3c9282"}}
```

`--json` emits just that machine-readable line. This is an example of the specified output, not a benchmark or an assertion that a particular environment was exercised.

## Small usage example

The harness is also usable from an unprivileged PHP CLI script. `Server` creates and owns a new private namespace; it never adopts or deletes a caller's existing directory.

```php
require 'src/bootstrap.php';

$server = new CommitLab\Server();
try {
    $response = $server->createBatch(['abc', 'xyz'], ['invoice label', '../not-a-path.php']);
    $batch = CommitLab\Scenario::json($response, 201);
    $snapshot = $server->getBatch($batch['id']);
    echo $snapshot['body'];
    $bytes = $server->readObject($batch['files'][0]['digest']);
    assert($bytes['body'] === 'abc');
} finally {
    $server->close();
}
```

The HTTP surface and `CommitLab\Repository` expose only `POST /batches` (`createBatch(files)`), `GET /batches/{id}` (`getBatch(batchId)`) and `GET /objects/{digest}` (`readObject(digest)`). Multipart uses one `labels` JSON field and a flat `files[]` list. Labels are unique UTF-8 metadata, not PHP filenames or paths. A batch contains 1–4 files, each 0–2 MiB. See the precise [contract](docs/contract.md) and [Portuguese API guide](docs/api.pt-BR.md).

## Why this design

All admission hashes finish before any staging or publication. The writer then takes one cooperating exclusive `flock`, reserves prospective retained state, streams private stages, installs complete digest-named objects and commits every batch association in one SQLite transaction. Readers get committed snapshots, and object reads verify regular-file metadata, exact byte size and SHA-256 digest before streaming bytes. Recovery takes the same lock, so it cannot collect an in-flight installed object. The concurrent test rendezvous is **before** this lock, not a serial-lock barrier waiting for a second writer.

## Limits and non-goals

The implementation bounds active harness clients/FPM children to 4, batches to 128, references to 512, installed objects including orphans to 128, application stages to 4, and observed object/staging logical bytes to 64 MiB. SQLite has a 2,048-page cap and observed 4 MiB WAL threshold. These are admission/accounting thresholds, **not physical disk quotas**. Parser/nginx temporaries are separate from application payload accounting.

nginx limits the request body to 9 MiB before FastCGI; admission invokes PHP's maintained explicit parser with the same bound before hashes or metadata publication. Post-parse checks and `memory_limit` do **not** establish a hard pre-parser RSS bound. PHP parser normalization is part of the documented subset, not a raw multipart conformance validator. The explicit parser throws when its 4-file / 5-part / 1-variable limits are exceeded; automatic POST parsing is disabled.

There is no authentication, malware scanning, rendered upload content, expiry, batch deletion, remote store or idempotency key. Digest equality means content identity, not origin authentication. A lost HTTP acknowledgement followed by retry can create another batch. Advisory locks require cooperation; hostile processes with the same UID, filesystem corruption and unkillable kernel I/O are outside the safety model. Normal filesystem/power-loss limitations remain: no cross-filesystem transaction or universal durability promise.
